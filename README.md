# LifeLedger

Personal productivity and finance app: tasks, habits, wallet and a currency converter. One Expo codebase runs on Android, iOS and the web, backed by an Express + MongoDB API.

The full spec and phase checklist are in [PLAN.md](PLAN.md). **Phases 1–7 are built: Work, Habits, Wallet + FX, Converter, Attendance, offline sync, PWA and release setup.**

```
apps/api         Express + Mongoose API (auth now; tasks/habits/wallet/fx/sync later)
apps/mobile      Expo app (Expo Router, NativeWind, TanStack Query, Zustand)
packages/shared  Types, Zod schemas, ISO 4217 currency table, money helpers
```

## Prerequisites
- Node.js 20+ (developed on Node 26).
- MongoDB:
  - **local**: `winget install MongoDB.Server` (runs as a Windows service on port 27017);
  - **or** a free MongoDB Atlas cluster (put its connection string in `MONGODB_URI`).
- On your phone: **Expo Go** from the Play Store or App Store.

## First-time setup
```bash
npm install
cp apps/api/.env.example apps/api/.env        # then put two long random strings in the JWT_* secrets
cp apps/mobile/.env.example apps/mobile/.env
npm run seed                                  # creates demo@lifeledger.app / Demo1234!
```
Generate each JWT secret with:
`node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`

## Run the API
```bash
npm run dev:api          # http://localhost:4000  (health: /api/v1/health)
```
In development, password-reset codes are **printed in this terminal** instead of being emailed.

## Run the app in a browser
```bash
npm run dev:app          # then press  w
```
It opens at http://localhost:8081. Use a window wider than 768 px to see the sidebar.

## Run the app on your phone (Expo Go)
1. Phone and PC must be on the **same Wi-Fi**.
2. Find your PC's IP: run `ipconfig` and look for the IPv4 address of your Wi-Fi adapter, e.g. `192.168.1.20`.
3. Edit `apps/mobile/.env` to `EXPO_PUBLIC_API_URL=http://192.168.1.20:4000`, using your IP.
4. Allow the API through Windows Firewall once, in an **admin** PowerShell:
   `New-NetFirewallRule -DisplayName "LifeLedger API" -Direction Inbound -LocalPort 4000 -Protocol TCP -Action Allow -Profile Private`
5. Start `npm run dev:api`, then `npm run dev:app`. Scan the QR code with Expo Go (Android), or with the Camera app on iPhone.
   - If the phone can't connect, run `npx expo start --tunnel` inside `apps/mobile`.

Note: in Expo Go, fingerprint unlock works on Android. **Face ID needs a development or EAS build on iPhone**; Expo Go cannot use it. The PIN works everywhere.

## Deploy
**API → Render (free) + MongoDB Atlas (free M0)**
1. Atlas: create a free M0 cluster.
   - Database Access: add a user. Network Access: allow `0.0.0.0/0` (Render's IPs change).
   - Copy the connection string, with the database name `lifeledger`.
2. Render → New → **Blueprint** → this GitHub repo. It reads `render.yaml`.
   - Paste `MONGODB_URI`, then set `WEB_URL` and `CORS_ORIGINS` to the web app's URL.
   - The JWT secrets are generated by Render.
3. Health check: `https://lifeledger-api-dknx.onrender.com/health` → `{"ok":true}`.
   - Free plan: the API sleeps after 15 min idle, so the first request then takes ~50 s.
   - Browser push alarms can't fire while it sleeps. Phone alarms are local, so they're unaffected.

**Web → Vercel**
- Import the repo. It reads `vercel.json`: it builds the Expo web export, proxies `/api/*` to Render (so sign-in cookies stay first-party), and adds an SPA fallback.

**CI**: `.github/workflows/ci.yml` runs lint, type-check and tests (with a MongoDB service) on every push.

## Offline & sync (Phase 7)
- Every record lives on the device: expo-sqlite on phones, IndexedDB in the browser.
- Every write goes to the device first, then to a sync queue.
- `POST /api/v1/sync` pushes the queue and pulls everything changed since the last sync.
  - It uses the server's write time (`syncedAt`), so edits made offline long ago still reach other devices.
  - When two devices edit the same record, the latest `updatedAt` wins. Deletes are soft (`deletedAt`) and propagate.
- Sync runs on start, on reconnect (web), on return to the app, every 5 min, and shortly after each edit.
- The header shows Synced / Syncing… / Offline (n pending); tap it to sync now.
- Exchange rates are cached on the device and labelled "Rates as of …" when offline.
- The web app is a PWA: a manifest, icons and an offline app shell (`public/sw.js`), with an "Install app" banner and Web Push for alarms.

## Release checklist (manual)
- [ ] **Airplane mode (phone):**
  1. Open the app, turn on airplane mode, tick a task, add an expense and mark attendance.
  2. The header shows "Offline (3 pending)".
  3. Turn airplane mode off and return to the app: it shows "Synced", and the changes appear in the browser after it syncs.
- [ ] **Conflict:**
  1. Edit the same task's title on the phone and in the browser, both offline.
  2. Reconnect both: the later edit wins everywhere.
- [ ] **PWA install:**
  1. Open the live site in Chrome or Edge, then use "Install app" (Home banner or Settings).
  2. The app opens in its own window.
  3. Go offline and reopen: it loads from cache and shows your data.
- [ ] **Web Push:**
  1. Settings → "Turn on notifications", then set a task alarm 2 minutes ahead.
  2. Close the tab: the notification arrives, if the API is awake.
- [ ] **APK:** install the EAS preview APK (allow "install unknown apps"), sign in, and check that the alarms and the fingerprint lock work.
- [ ] **Health:** `/health` on the API returns `{"ok":true}`; the API sends security headers (HSTS etc.).

## How auth works (Phase 1)
- **Access token**: a JWT valid for 15 min, kept in memory.
- **Refresh token**: random, valid for 30 days.
  - It rotates on every use. The server stores only an HMAC of it, in the `sessions` collection.
  - Replaying an already-rotated token signs out every device.
  - Native apps keep it in the Keychain/Keystore (expo-secure-store). The web keeps it in an `httpOnly` cookie. "Remember this device" off means a browser-session cookie and a 1-day session.
- **Sign-in lockout**: 5 wrong passwords within 15 min lock the account for 15 min.
- **Reset codes**: 6 digits, valid for 10 min. A code is burned after 5 wrong tries, and a successful reset signs out every device.
- **App lock** (optional, per device): None / PIN / Biometric with the PIN as backup.
  - The refresh token is read from secure storage only after a successful unlock.
  - 3 failed biometric tries fall back to the PIN. 5 wrong PINs require a full password sign-in.
  - On the web, the PIN is a convenience lock for that browser.
